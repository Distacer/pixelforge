# Архітектура

## Загальна схема

```
Браузер
┌──────────────────────────────────────────────────────────────────────┐
│ React SPA                                                            │
│                                                                      │
│  pages/ ──▶ features/ ──▶ shared/lib  (чисті функції, без React)     │
│                │                                                     │
│                ▼                                                     │
│   Zustand-стори: editor · auth · settings · toasts                   │
│        │                  │                                          │
│        ▼                  ▼                                          │
│   localStorage       shared/api/client.ts  ── fetch + JWT ──┐        │
│  (чернетка, тема,                                           │        │
│   мова, токен)                                              │        │
└─────────────────────────────────────────────────────────────┼────────┘
                                                              │ /api/*
              dev: Vite proxy  ·  Docker: nginx               │
                                                              ▼
┌──────────────────────────────────────────────────────────────────────┐
│ FastAPI                                                              │
│  routers/ (auth, users, artworks, gallery)                           │
│      │ Depends(get_db), Depends(get_current_user)                    │
│      ▼                                                               │
│  services/ ──▶ SQLAlchemy ORM ──▶ SQLite (users, artworks, likes)    │
└──────────────────────────────────────────────────────────────────────┘
```

## Як рухаються дані

### Малювання

1. Користувач веде мишею по полотну → `PixelCanvas` переводить координати екрана в координати пікселя.
2. Інструмент (олівець, заливка…) рахує нові пікселі **чистою функцією** з `shared/lib`.
3. Результат іде в `useEditor.setCel(...)` — стор створює новий об'єкт документа.
4. Полотно підписане на стор і перемальовується в наступному `requestAnimationFrame`.
5. Через 0.5 с після останньої зміни документ стискається RLE й пишеться в `localStorage`.

React-компоненти редактора при цьому не перерендерюються на кожен рух миші — лише canvas.

### Збереження на сервер

```
EditorTopBar «Зберегти»
  → useSaveArtwork()
     → serializeDoc(doc)          RLE-стиснення шарів і кадрів
     → makePreviewDataUrl(doc)    PNG першого кадру ~256px
     → POST /api/artworks         (або PATCH, якщо робота вже є)
  ← { id, ... } → URL стає /editor/:id
```

Сервер зберігає документ як JSON-текст, а прев'ю — як BLOB у тій самій SQLite-базі.
Галерея показує лише прев'ю; повний документ вантажиться, коли роботу відкривають
у редакторі або переглядають анімацію.

### Авторизація

```
POST /api/auth/register {username, password}
  → bcrypt(password) → INSERT users
  ← { access_token: JWT(sub=user_id, exp=+7 днів), user }

Фронтенд кладе токен у localStorage (persist у Zustand)
і додає заголовок  Authorization: Bearer <token>  до кожного запиту.

Бекенд: Depends(get_current_user) → decode JWT → users.get(id) → або 401.
Якщо прийшов 401 — фронтенд сам виходить з акаунта.
```

## Ключові рішення

| Рішення | Чому |
|---|---|
| **Документ як масив чисел `0xRRGGBBAA`** | піксель — одне число; копіювання шару = `slice()`; порівняння — `===`; просто серіалізувати |
| **Незмінний (immutable) документ** | undo/redo — це просто стек посилань на старі документи; змінений лише один шар, решта спільна |
| **Шари спільні для всіх кадрів, пікселі — у «клітинках» `frame.cels[layerId]`** | так працюють професійні редактори (Aseprite); можна сховати шар одразу в усій анімації |
| **Рендер canvas поза React** | 60 fps при малюванні; React відповідає лише за панелі |
| **RLE для збереження** | піксель-арт — це великі однотонні ділянки; документ 64×64 з 10 кадрами стискається з ~400 КБ до кількох КБ |
| **Власний GIF-кодувальник** | демонструє розуміння формату (LZW); жодних залежностей |
| **Прев'ю генерує клієнт** | бекенду не потрібні Pillow чи рендер; він лише перевіряє, що це справжній PNG |
| **SQLite** | один файл, нуль налаштувань, достатньо для навчального проєкту; через SQLAlchemy легко замінити на PostgreSQL |
| **Унікальність ніку через `username_key = casefold()`** | `lower()` у SQLite не знає кирилиці — «Іван» і «іван» були б різними акаунтами |
| **Zustand замість Redux** | мінімум шаблонного коду, селектори без зайвих ре-рендерів, доступ до стану поза React |
| **Tailwind + CSS-змінні** | теми перемикаються зміною класу `.dark` на `<html>`, без перерахунку стилів у JS |
| **Feature-based структура папок** | усе, що стосується редактора, — в одній папці; `shared/` не знає про фічі |

## Межі модулів

```
pages      → можуть імпортувати features, shared, store
features   → можуть імпортувати shared, store, інші features (editor ← gallery, upload)
shared     → не імпортує нічого з features/pages (крім store/auth в api-клієнті)
shared/lib → чистий TypeScript без React і без DOM-залежностей там, де це можливо
```

Через це алгоритми з `shared/lib` тестуються у Node без браузера.

## Безпека

- паролі — лише bcrypt-хеші; перевірка займає однаковий час для існуючих і неіснуючих ніків;
- JWT підписується секретом із `JWT_SECRET`; у токені лише id користувача;
- приватні роботи віддаються лише власнику; на чужі запити — `404`, щоб не розкривати факт існування;
- редагувати/видаляти можна лише свої роботи (`403`);
- завантажений файл перевіряється за сигнатурою PNG, а не за розширенням; обмежено розмір і сторону;
- розмір JSON-документа обмежений (`MAX_DOC_BYTES`), розмір запиту — `client_max_body_size` у nginx.

## Що можна розвинути

- міграції бази через Alembic замість `create_all`;
- refresh-токени та httpOnly cookie замість localStorage;
- коментарі й підписки на авторів;
- спільне редагування в реальному часі через WebSocket;
- інструмент виділення та переміщення фрагментів, градієнтна заливка, власні пензлі.
